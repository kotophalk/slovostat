# Архитектура

## Задача

Веб-сервис для подсчёта слов и символов на странице по URL. Аудитория —
SEO-специалисты на российском рынке. Unix way: одна функция, но качественно.

Требования, из которых выросла текущая структура:

- На выходе: слов, символов с пробелами, символов без пробелов.
- Считается только видимый текст — без скриптов, стилей и мета-тегов.
- Интерфейс на русском.
- Rate limiting по IP, лимит легко менять.
- Новые метрики (кириллица, латиница, цифры, эмодзи) добавляются без
  переписывания.
- Docker для деплоя, локальный запуск для разработки.
- Python 3.11+, FastAPI, pip + requirements.txt.

## Стек

| Что | Зачем |
|---|---|
| FastAPI + Jinja2 | один роут API и одна HTML-страница |
| httpx (async) | загрузка страниц, потоковое чтение с лимитом |
| beautifulsoup4 | извлечение видимого текста и определение кодировки |
| aiosqlite | счётчики запросов для rate limiting |

## Модули

```
app/
├── main.py       FastAPI: роуты, lifespan (открытие/закрытие БД)
├── clientip.py   IP клиента с учётом reverse proxy
├── limiter.py    rate limiting на SQLite
├── fetcher.py    загрузка страницы, проверки цели, извлечение текста
├── counter.py    реестр метрик и подсчёт
├── config.py     все настройки из переменных окружения
└── templates/
    ├── index.html    главная; счётчик Метрики и cookie-уведомление — только при SLOVOSTAT_METRIKA_ID
    └── privacy.html  политика конфиденциальности (/privacy)
```

Каждый модуль знает только о `config` и о себе; связывает их `main.py`.

## Поток запроса

```
Пользователь → POST /analyze
  ├── get_client_ip      X-Forwarded-For, если запрос от доверенного прокси
  ├── check_limit        превышен → 429
  ├── record_request     списываем попытку ДО загрузки
  ├── fetch_visible_text ошибка → 422
  │     ├── _check_target      схема, резолв, публичность адреса
  │     ├── редирект?          → новый URL, снова _check_target (до 5 раз)
  │     ├── _check_content_type
  │     ├── _read_limited      обрыв на лимите размера
  │     └── extract_visible_text
  └── count_text → JSON с метриками
```

## Принятые решения

**Редиректы обрабатываются вручную.** С `follow_redirects=True` проверка цели
осталась бы только на первом URL: сайт отвечает `302` на `http://10.0.0.5/` и
уводит запрос во внутреннюю сеть. Поэтому `follow_redirects=False` и цикл, где
каждый следующий URL проверяется заново.

**Адрес проверяется через `is_global`.** Это отсекает разом localhost, приватные
сети, link-local (включая `169.254.169.254` — метаданные облака), CGNAT и
зарезервированные диапазоны. IPv4-mapped IPv6 разворачивается перед проверкой.

Остаточный риск: между проверкой и соединением httpx резолвит имя заново, так
что DNS rebinding теоретически возможен. Полностью закрывается только
подключением к уже проверенному IP — на текущем масштабе не окупается.

**Лимит списывается до загрузки.** Если считать только успешные запросы, перебор
несуществующих или запрещённых URL не стоит ничего, и сервис превращается в
бесплатный сканер чужих сайтов.

**`X-Forwarded-For` — только от доверенных адресов.** За reverse proxy
`request.client.host` всегда равен адресу прокси, и без разбора заголовка лимит
становится общим на всех. Но доверять заголовку безусловно нельзя: клиент
подставит любой адрес и получит новую квоту. Компромисс — список доверенных
сетей в `TRUSTED_PROXIES` и обход цепочки справа налево.

**Одно соединение с SQLite на процесс.** Раньше каждый вызов открывал файл,
создавал таблицу и закрывал соединение. Теперь схема и индекс `(ip, timestamp)`
создаются один раз в `init_db`, включён WAL, а чистка старых записей идёт раз в
100 вставок вместо каждой.

**Метрики описаны одним списком.** `METRICS` в `counter.py` задаёт ключ, подпись
и функцию подсчёта; по нему строится и JSON-ответ, и блоки на странице. См.
[development.md](development.md).
